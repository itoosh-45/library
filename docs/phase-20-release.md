# שלב 20 — פרסום באישור משתמש עם בדיקות פתוחות

ב־3 באוקטובר 2026 המשתמש אישר במפורש: ״מאשר לפרסם את התוצר בכל מקרה גם אם לא עשית 100% מהבדיקות״. האישור מחליף את ההמתנה להשלמת כל בדיקות הקבלה לפני פרסום; הוא אינו הופך NOT RUN ל־PASS ואינו מבטל את איסור התשלום. גרסת הפרסום היא App 0.16.0, schema 2, JSON 8, Excel 1, מהבנייה הקפואה של e2c5a91a7c8e8b5b35a73d3ae3d3beccb4ec19f4. תיקון המכסה ב־main הוא שירות שרת ואינו משנה את קבצי האתר.

## מסלול הפרסום

האתר נמסר דרך GitHub Pages הקיים במאגר הציבורי, מענף product-pages ובנתיב /. מעתיקים רק את 21 קבצי הבנייה שנבדקו, משווים כל SHA256 לרישום staging ומוסיפים .nojekyll ריק. אין בנייה מחדש, מפתחות, נתוני ספרייה או שרת gateway בענף הפרסום. camera-demo-archive נשמר ללא שינוי לצורך היסטוריה וחזרה לאתר הקודם. main מחזיק את המקור והתיעוד; מיזוגים רגילים אליו אינם מפרסמים אוטומטית.

זהו אירוח Pages ציבורי הזמין ב־GitHub Free ובחשבון הקיים: [תיעוד GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages). אין רכישה, שינוי תוכנית, חיוב, כרטיס, דומיין חדש או שירות אירוח נוסף. לא נוצר workflow מותאם שמעלה ארכיון Actions; מסלול הענף הקיים נשאר מנוהל על ידי Pages. אין להוסיף שירותים בתשלום או להגדיל מכסות אחסון.

## כלי קבלה מקומי אופציונלי

release/candidate.py משתמש רק בספרייה התקנית של Python 3.12. `pack` אורז snapshot פרטי ויוצר קבלה במצב NOT RUN/userReady=false. `verify` מסרב לתוצאה חסרה, commit שונה, hash שונה, קבצים זרים, קישורים, traversal, ארכיון גדול, דפוסי מפתח או CSP חסר. הוא כותב לתיקייה חדשה בתוך workspace רק אחרי האימות. אין בו גישה לרשת או פרסום. אין להשתמש ב־freeOnly=true כראיה למצב חשבון או למכסה כספית; זה שדה הצהרה בלבד.

המנגנון המחמיר אינו מסלול הפרסום החריג שאושר לעיל. אין למלא PASS סינתטי בקבלת הגרסה האמיתית כדי לעקוף אותו. בדיקות היחידה משתמשות בקבלה מסומנת SYNTHETIC בלבד. הראיות האנושיות נשארות באחריות התיעוד והסקירה; כלי hashes אינו מוכיח שמצלמה, API או טלפון נבדקו.

בדיקה ממוקדת: `python -m unittest discover -s release -v`. שבע בדיקות עברו; ניסוי תקלה יחיד הפך את השוואת commit והכשיל את בדיקת commit הזר, ואז הקובץ שוחזר וכל שבע הבדיקות עברו. CI נוסף רץ רק במאגר ציבורי על runner רגיל, ללא העלאת artifacts או התקנת ספריות Python. לא חוזרים על בדיקות frontend שעברו ללא שינוי frontend.

ביקורת לפני מיזוג: נכונות — snapshot וראיות קשורים ל־commit; פשטות — קובץ כלי אחד, ללא תלות/שרת; מבנה — מופרד מהמוצר ומה־gateway; אבטחה — רשימת קבצים מוגבלת, כתיבה אחרי אימות, ללא extractall/מפתחות/נתונים; ביצועים — עד 128 קבצים, 5MB לקובץ ו־20MB לתוכן, כולל חסם התרחבות gzip. סריקת דפוסי מפתח אינה הוכחה שאין כל סוד אפשרי. אין אימות host/auth של gateway ציבורי ואין הפעלתו בפרסום זה.

## בדיקת אתר וגבולות

לאחר הפרסום מאמתים HTTPS, hashes של הקבצים, manifest/scope, פתיחה ורענון hash route, יצירת ספר סינתטי, גיבוי ושחזור מוגן בסביבת דפדפן נפרדת ואופליין אחרי טעינה. אין להשתמש בספרייה אישית בבדיקות הסוכן. אין קריאות זיהוי בתשלום או שימוש במפתח משתמש.

הבדיקות הפתוחות נמצאות ב־docs/phase-19-acceptance.md: iPhone/מצלמה/VoiceOver/Files/update של התקנה קיימת, מדגם אמת של AI וקטלוגים חיים מלאים. NLI ו־Google Books אינם פעילים ללא gateway ציבורי מאומת; Open Library זמין ישירות, ו־Gemini דורש מפתח אישי Free בזיכרון והסכמה. ההרשאה לפרסום אינה מבטיחה שהיכולות החיות נבדקו. n8n נשאר ללא שינוי. יש להוריד JSON מלא ולשמור ולבדוק אותו לפני שימוש משמעותי; Excel אינו גיבוי תמונות מלא.

חזרה: אפשר להחזיר את מקור Pages אל camera-demo-archive כדי להפסיק הצגת מוצר, בלי למחוק IndexedDB או נתוני משתמש. לפני עדכון מוצר או שחזור גרסה יש לקרוא docs/upgrade-origin-runbook.md ולהגן בגיבוי JSON; אין לבצע downgrade של DB או מחיקה כדי לתקן UI.

## תוצאת הפרסום — 3 באוקטובר 2026

[האתר הציבורי](https://itoosh-45.github.io/library/) פורסם בהצלחה ב־HTTPS. Pages legacy, source product-pages:/, commit 24b527639153c544f95862bed5d74b69564d637d; [הרצת הפרסום](https://github.com/itoosh-45/library/actions/runs/37138009908) עברה. כל 21 קבצי המוצר שהתקבלו בפועל ב־HTTPS תאמו SHA256 של הבנייה הקפואה, בנוסף ל־.nojekyll ריק. לפני ההצלחה הבדיקה זיהתה את אתר המצלמה הישן, ובדיקה של Git blobs זיהתה נרמול שורות ברישיון הפונט בלבד; הרישיון נשמר מחדש בבתים המקוריים, בלי שינוי frontend ובלי force push, והפרסום הופעל. הריצה הכפולה שנוצרה ב־Pages בוטלה על ידי השירות; הריצה הסופית הצליחה.

T28 smoke שולחני ממוקד עבר: manifest/scope מדויקים, שליטה של service worker, רענון hash route בהגדרות, ספר סינתטי, הורדת JSON, שחזור מגן מפורש ב־context ריק והשוואת כל tables, רענון אופליין והורדת גיבוי תקין, ללא page errors. כל HTTPS חיצוני ב־context העיקרי נחסם; אין בקשות ספקים או מפתחות. הבדיקה נמצאת ב־tests/compatibility/production.spec.ts וב־playwright.production.config.ts; נדרש manifest הפרטי שנשמר עם snapshot. ריצה סופית: בדיקה אחת עברה ב־14.7 שניות. ההשוואה באופליין אומתה מול exportedAt לחותמת lastBackupAt שנוספה אחרי ההורדה הראשונה, ואז שאר הנתונים הושוו במדויק. זה תיקון בדיקה, לא שינוי מוצר.

typecheck ו־lint עברו לבדיקת production. [CI main להכנת השחרור](https://github.com/itoosh-45/library/actions/runs/37137730892) עבר, כולל שבע בדיקות כלי הקבלה. תוצאות frontend הקודמות נשארות בתוקף כי הבנייה לא השתנתה. נשאלה בדיקת טלפון על פתיחה והורדת JSON; אין תשובה בשעת התיעוד. T28 המלא ושער 10 נשארים PARTIAL בגלל הבדיקות החיות והטלפון המפורטות לעיל; אין הכרזה שכל שערי הפרויקט עברו.

שלב 20 השלים את הפרסום והמסירה באישור החריג של המשתמש. ממשיכים לשלב 21 כעת, בלי להחזיר את הבדיקות שהמשתמש ויתר על המתנתן כחסם, ובמקביל שומרים אותן פתוחות ביומן הראיות. תג v0.16.0-preview.1 מצביע לבנייה הציבורית; הוא אינו tag של candidate שעבר את כל השערים.
