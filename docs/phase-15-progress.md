# שלב 15 — גיבוי JSON מלא ומיזוג

3 באוקטובר 2026. App 0.13.0, DB schema 2, יצוא JSON 8 וקריאת 1–8. הבנייה המקומית הושלמה; מחזור 8 עדיין פתוח עד שלב 16 והראיות התלויות במכשיר. WORK_PLAN.md נשמר ללא שינוי.

## התנהגות

יצוא מכל הטבלאות הקבועות ותמונות מתוך snapshot עקבי, עם מעטפת הספר, ספירות ו־SHA-256. מפתחות, מטמון ותשובות ספק גולמיות אינם יוצאים. ההורדה מופרדת מאישור המשתמש שהקובץ נשמר ונבדק; תזכורת בתוך המסך אחרי 30 יום. המשתמש דיווח שההבחנה בין הפקה לאישור ובין החלפה למיזוג ברורה. זו ראיית בהירות ממשק בלבד.

החלפה ומיזוג מחייבים preview, גיבוי מגן ואישור. המיזוג שומר רשומות חסרות בקובץ ואת שם/הגדרות ספריית היעד. לכל סתירה בוחרים גרסה במפורש. בין ספריות מזהים ממופים באופן דטרמיניסטי, כולל קשרים, טיוטות והמקור הנגזר של זיהוי שנשמר. ספרים דומים ואוספים בעלי שם מתנגש נשמרים בנפרד אחרי אישור; אין איחוד מהדורות לפי שם. כל התוצאה מאומתת לפני transaction אחת, עם בדיקת שינוי נוספת בתוכה. ייבוא חוזר אינו מוסיף שוב את אותן רשומות.

## קובץ גדול וזיכרון

Production מקומי, Chrome 154, viewport של 390×844 על מחשב Windows; אין זו בדיקת טלפון. 1,000 ספרים, 1,600 עותקים, 2,000 השאלות היסטוריות ו־50 פתוחות, 1,000 JPEG סינתטיים תקינים. קובץ 148,975,601 bytes (כ־142.1MiB), תמונות גולמיות 109,949,000 bytes. אימות, גיבוי מגן, שחזור, יצוא, רענון וספירות/כריכות עברו ללא שגיאות דף. התקרה בקוד 157,286,400 bytes (150MiB), ונבדקת גם לפי UTF-8.

שתי ריצות השוואה הושלמו לפני הוראת המשתמש לחצות ניסויים. לפני צמצום עותקי JSON: אימות 12,521ms, שחזור 17,022ms, יצוא 24,781ms; דגימת V8 heap מרבית 1,220,091,424 bytes. אחרי השינוי: 25,762ms, 30,576ms, 24,792ms; דגימה מרבית 967,322,080 bytes. אין ראיה לשיפור בזמן. דגימת CDP כל 200ms מתעכבת בעבודה סינכרונית ואינה כוללת Blob/native או את כל זיכרון התהליך; אין להציג אותה כ־peak memory מלא. ההפחתה שנצפתה עדיין מותירה צריכת זיכרון גבוהה. אין הבטחת קובץ כזה ב־iPhone. פלטים פרטיים ב־private/phase15-benchmark אינם ב־Git.

נמנעה ריצה חוזרת של benchmark רגיל של 1,000 ספרים לפי ההוראה לחצות ניסויים. מספרי שלב 14 נשארים ראיה היסטורית; הם לא מדידה חוזרת של 0.13.0.

## ביקורת לפני מיזוג

נכונות: אימות מקור ותוצאה משולבת, מיפוי כל קשרי Core, fingerprint לפני ההכנה ובתוך הכתיבה, rollback וייבוא חוזר. קריאות: UI סקירת סתירות נפרד; פורמט, מעקב גיבוי ומיזוג במודולים ממוקדים. ארכיטקטורה: שימוש באותו validator, ללא DB schema חדש או dependency. אבטחה: רשימת שדות מותרת ביצוא/ייבוא, תקרת נפח, ללא רשת/סודות במסלול, הצגת טקסט דרך React. ביצועים: בלי serialization/parse חוזר של מעטפת היצוא ובלי hash כפול; מגבלת הזיכרון נשארת מתועדת.

בדיקת ביקורת הפיכה בוצעה בעותק פרטי בלבד, בלי לשנות את מקור השרת האישי: הסרת עדכון recordId הנגזר גרמה לבדיקה של סקירת מדף שנשמרה להיכשל; החזרת השורה העבירה אותה. התקלה והתיקון נבדקו לפני הוראת צמצום הניסויים. לא הופעל סוכן נוסף.
