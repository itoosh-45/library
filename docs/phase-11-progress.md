# שלב 11 — תור תמונות וטיוטה מקומית

App 0.9.0, סכימת מסד 2, גיבוי v6. נבנו חוזה shelf-v1, תור סדרתי, טיוטת batch עם batchId/itemId/imageId קבועים, מדף יעד ורשימה אחת של תמונות ותוצאות. מקור נבחר לשמירה במפורש, מוקטן ומקודד מחדש בלי metadata. ללא מקור שמור, אחרי סגירה נדרשת בחירה מחדש לפי hash; תוצאות שהושלמו נשארות בטיוטה.

תוצאה נשמרת לפני התמונה הבאה. השהיה מסמנת בקשה שנקטעה ואינה שולחת אותה שוב; ניסיון נוסף דורש אישור פרטני וחידוש מפורש. בעלות runId נשמרת במסד: חלון שני אינו מתחיל תור פעיל, ופלט אחרי החלפת בעלות אינו נשמר. תום מכסה ושגיאת רשת עוצרים ללא retry ומותירים את התוצאות הקודמות. אין כתיבה ל־books או copies בשלב זה.

חפיפות ומזהים זהים יוצרים הצעה בלבד; שני עותקים וכרכים נשארים פריטים נפרדים. מספר התמונות הכולל אינו מוגבל מוצרית. יש גבולות בטיחות לקובץ ולתוצאת תמונה אחת (עד 40 פריטים), בקשה אחת בכל רגע ומקור מפוענח אחד בכל הכנה. תצוגת מקור פותחת תמונה אחת לפי בחירה.

גיבוי v6 כולל טיוטות, מקורות שמורים והראיות. מקבל v1–v5 עם טיוטות ריקות באופן מפורש. קשרי מדף/תמונה/פריט שמור, checksum ותוכן תמונה נבדקים; החלפה אטומית אינה מנקה את הטיוטות ששוחזרו. מחיקת מדף מסירה רק את שיוך הטיוטה; ניקוי תמונת ספר או מדף אינו מוחק מקור שעדיין קשור לטיוטה. מחיקת מקור מותירה תוצאות.

## בדיקות

npm run check עבר: טיפוסים, lint, 131 בדיקות Vitest, ארבע בדיקות Node ובניית לקוח ושירות. עשר בדיקות שלב 11 כוללות תמונות סדרתיות, IDs וחפיפות, פלט פגום, השהיה, בעלות חלון, מקור חסר, quota ורשת, rollback של מקור וטיוטה, סגירה בזמן הכנה, גיבוי ושחזור מקור 2048px וקבלת v5. fixtures היסטוריים הותאמו לתכולת גרסתם; הוולידציה אינה מתירה ישויות חדשות בתוך גיבוי ישן.

שלוש בדיקות UI ייעודיות עברו: בחירת כמה קבצים, שליחה מפורשת, חפיפות נפרדות, מקור וגיבוי, רענון ללא מפתח, התאמת קובץ חסר, quota והשהיה. מקור JPEG מוכן בדפדפן אמיתי; כל Gemini מדומה ומפתח הדמה אינו ב־export או console. כל 35 בדיקות הדפדפן עברו (1.3 דקות), כולל שלבים קודמים ורוחב 360px.

ניסוי רגישות הפיך הסיר את הגנת runId; בדיקת תוצאה מאוחרת נכשלה כמצופה. המקור הוחזר לפני הריצה המלאה. פלט הניסוי מוחרג מ־Git.

## ביקורת קוד

נכונות: תוצאות לפי תמונה, מזהים יציבים, כתיבה סדרתית, עסקאות ותגובה מאוחרת שאינה נכנסת למסד. קריאות: חוזה הזיהוי, שירות טיוטות ותור, UI וגיבוי מחולקים לפי אחריות. ארכיטקטורה: אותו מסד ו־VisionSession, מסך עצל, ללא ספק חדש או תלות חדשה.

אבטחה: נעילת תשלומים והסכמה משלב 10 נשמרות; API מדומה בבדיקות, מקור JPEG מוגבל ומאומת בחתימה/ממדים/hash לפני שליחה, וראיות ספק עוברות whitelist. אין מקור או מפתח שנשמרים אוטומטית. ביצועים: אין פענוח כל התמונות מראש; File handles נשמרים זמנית בלי תמונות מפוענחות, המקורות השמורים נטענים אחד בכל עיבוד. התאמות חפיפה כרגע השוואה זוגית; מדידות 1000/5000 ומיטוב לפי ראיות בשלב 14.

## ראיות חסרות והמשך

חמישה אזורי מדף, 2–3 תמונות לכל אזור, 50 ספרים קריאים, ground truth ו־holdout: NOT RUN. אין מדדי recall/precision אמיתיים או הוכחת iPhone. שאלת UI הוצגה למשתמש; היעדר תשובה אינו עוצר עבודה עצמאית. שער 6 אינו מושלם. שלב 12 מוסיף עריכה, בחירת קטלוג, עוד עותק/ספר חדש ושמירת מאושרים בלבד; התוצאות כעת הן טיוטה ללא ספרים חדשים.

בבדיקה החזותית תוקן מספור כפול ו־bdi לשם קובץ. בחירת קובץ מחדש לתצוגת מקור אינה שולחת אותו שוב. לאחר הוספת הגנת סגירה, בדיקות UI חשפו lifecycle של StrictMode שסימן מסך חדש כסגור; הוספת activate ב־mount מתקנת זאת בלי לשנות מצב מכסה או בעלות תור. בדיקת סגירה בזמן הכנה מונעת הוספת תמונה מאוחרת.
