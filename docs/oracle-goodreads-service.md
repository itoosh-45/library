# Goodreads ב־Oracle — התקנה מבודדת, 7 באוקטובר 2026

המשתמש ביקש להתקין בשרת Oracle הקיים לאחר בדיקת מקום ועומס. החיבור נעשה במפתח SSH הקיים, ללא שינוי שירותי n8n, פתיחת פורט ציבורי חדש, תשלום או ספק scraping חיצוני. מקור השירות נמצא ב־`gateway/goodreads/`; App 0.24.0 מחבר את השירות לחיפוש הקיים לפי שם, מחבר או ISBN, ללא שדה להזנת קישור.

## בדיקת קיבולת

Ubuntu 24.04, ARM64, שתי ליבות, כ־11.65GiB RAM. לפני ההתקנה היו כ־10GB זיכרון זמינים, 36GB דיסק פנויים ועומס 0.22/0.09/0.02. n8n ושאר השירותים היו בעומס נמוך. התמונה הבסיסית תופסת כ־237MB; קובצי השירות, מסד הנתונים והמפתח היו כ־144KB אחרי השליפה. בדיסק נשארו כ־35GB. אלה מדידות נקודתיות, לא הבטחה לעומס בכל שעה.

## פריסה ומגבלות

- Docker עצמאי בשם `library-goodreads`, תחת `/opt/library-goodreads`, ברשת `proxy-net` הקיימת. אין Node או חבילות חדשות על מערכת ההפעלה.
- הנתיב המאובטח הוא `https://maya-n8n.duckdns.org/library-catalog/`. נתיב `/` ממשיך להגיע ל־n8n. Nginx Proxy Manager טען קובץ חדש `/home/ubuntu/docker/npm/data/nginx/custom/server_proxy.conf` אחרי `nginx -t`; בוצע reload בלבד, ללא restart של שירות קיים. הקובץ נשמר ב־volume של הפרוקסי ובנפרד מקובץ ה־host המנוהל.
- Docker מוגבל ל־192MiB, ללא swap נוסף, 0.25 ליבת CPU ו־64 תהליכים. משתמש לא־root, מערכת קבצים לקריאה בלבד, ללא capabilities, ללא העלאת הרשאות. האחסון והמפתח מורכבים בנפרד; המפתח לקריאה בלבד. פורט 4336 נגיש רק ב־127.0.0.1 של השרת.
- `unless-stopped` מחזיר את השירות לאחר הפעלה מחדש. healthcheck כל 60 שניות הוא בדיקת זמינות התהליך בלבד; הוא אינו פונה ל־Goodreads ואינו מוכיח זמינות המקור. Docker אינו מפעיל מחדש תהליך רק משום שסומן unhealthy.
- פנייה אחת למקור בכל פעם, לפחות 10 שניות בין פניות, 200 reservations ליום UTC. כל reservation נשמר לפני פנייה ואינו מוחזר בכשל. המכסה וההמתנה משתמשות ברכיב SQLite העמיד הקיים, עם ספק Goodreads במסד חדש ונפרד מה־gateway המקומי. אין איפוס מכסה בהפעלה מחדש.
- 30 בקשות API בדקה, 32 חיבורים, גוף עד 1KB, תשובת מקור עד 2MB, timeout של 15 שניות לשליפה. חסימה של חיפוש משהה חיפושים ל־6 שעות, בנפרד משליפת פרטי מהדורה ולחיפוש ISBN. חסימת דף ספר משהה פניות חדשות למקור ל־6 שעות; cache קיים נשאר זמין. כשל לא ודאי משאיר את ההמתנה השמרנית של ה־ledger, עד 24 שעות. אין retry אוטומטי או ניסיון לעקוף חסימה.
- מטמון עד 200 תוצאות ל־24 שעות; מפתח חיפוש נשמר כ־SHA256 ולא כטקסט החיפוש. רק מידע מנורמל על ספר נשמר, בלי HTML מלא, ביקורות או ספריית משתמש. לוג Docker עד שני קבצים של 5MB; לוג גישה לנתיב כבוי.

תמונת Node הבסיסית בפריסה ננעלה ל־`node@sha256:ebfe2f90462722a7a4de65e91990e97fe0d401c70e0e762c5b53302f905ec1c1`; ההתקנה שומרת את ה־digest ב־`/opt/library-goodreads/node-image.txt`. לאחר תיקוני הכריכות ובידוד חסימת החיפוש השירות משתמש בתמונה המקומית `library-goodreads:2`. לא נעשה שימוש בנתוני ספרייה או תמונות פרטיות.

## חוזה API והרשאות

GET `/health` מחזיר מצב התהליך בלבד, בלי מפתח. כל השליפות הן POST עם `Content-Type: application/json` ו־`Authorization: Bearer <private token>`:

- `/v1/book` מקבל `{ "id": "247411944" }`, או URL תקין של דף Goodreads. היעד בפועל תמיד נבנה ממזהה מספרי תחת host קבוע; URL משתמש לא נשלח ישירות לרשת.
- בחיפוש ISBN תקין נשלח מספר הספר לנתיב הציבורי `/book/isbn/`; הפניה רגילה מאומתת למזהה Goodreads מוחזרת כמועמד בלי לעקוב אחר URL חיצוני. אין עקיפת חסימת שם באמצעות proxy או זהות חלופית.
- `/v1/search` מקבל `{ "query": "שם ספר או ISBN" }` ומחזיר עד חמישה מזהי ספרים וקישורים. בוחרים מזהה ומבקשים פרטי מהדורה בנפרד, כדי לא לשייך כריכה או ISBN של מהדורה אחרת אוטומטית.

הפרטים כוללים שדות מהדורה, מחברים בתפקיד Author בלבד, סדרה ומספר אם קיימים, וכתובת כריכה רק משרתים מורשים. אין ניחוש של פיצול שם מחבר, סיכום ספר או יום פרסום חסר. מתאם האפליקציה מאמת מזהה, כתובת מקור, שדות וכתובת כריכה, וממפה סדרה למודל הסדרות הקיים. מפתח הגישה נשמר בנפרד מהספרייה ומגיבויי JSON ו־Excel. בחירת מועמד טוענת פרטים ו־JPEG מקומי; רק שמירת הספר יוצרת שיוך לסדרה. אין מפתח מובנה בתוך build ציבורי.

Origin של האפליקציה (`https://itoosh-45.github.io`) מותר, אך CORS אינו תחליף למפתח. מפתח פרטי בן 256 ביט נוצר בשרת, מוגן בהרשאות 0400 ונשמר ב־`/opt/library-goodreads/secrets/library-token`. עותק החיבור המקומי נמצא תחת `private/oracle-goodreads-connection.json`, מוחרג מ־Git. אין להעביר מפתח לצ׳אט או ל־VITE_*.

## אימות שנעשה

`npm run check` עבר: 214 בדיקות יחידה, 15 בדיקות Node, טיפוסים, lint ושתי בניות. Chrome: 24 בדיקות שונות (23 בסבב המלא והבדיקה הנוספת בסבב Goodreads ממוקד). PWA: 11 בדיקות שונות (10 בסבב מלא והבדיקה הנוספת בסבב ממוקד). WebKit ב־Windows: תשע עברו ואחת דולגה במפורש בגלל כשל Blob ב־IndexedDB ששוחזר ב־API דפדפן נקי ללא קוד האפליקציה; טקסט ו־Uint8Array כן נשמרו. אין שינוי בסכמת התמונות כדי לעקוף מגבלה של סביבת הבדיקה. שמירת כריכה ב־Safari פיזי נשארת NOT RUN.

נבדקו החיפוש הרגיל, בחירה לפני שמירה, תאריך וסוג כריכה, שינוי ידני של סדרה, שימור מידע ישן, JSON מלא 12/basic 9 לפי הצורך ו־Excel 4, מחיקת מפתח וזמינות המקורות האחרים בזמן חסימה. אין שדה קישור חדש. ניסוי mutation הסיר זמנית בדיקת token: בדיקת HTTP נכשלה על 200 במקום 401; ניסוי נוסף הפך את התאמת מזהה המהדורה במתאם והכשיל את בדיקות הזיהוי. שני התנאים שוחזרו והבדיקות עברו.

ביקורת לפני מיזוג: נכונות — קשרים ושדות מהדורה עוברים validation ושחזור; פשטות — Node/SQLite מובנים וללא ספק בתשלום; מבנה — שירות מבודד ומתאם קטלוג קיים; אבטחה — token, origin, יעד קבוע, שדות מוגבלים, בלי סודות בבנייה; ביצועים — מגבלות Docker, תור, cache ומכסה עמידה. אין שינוי לתהליך ה־AI ואין קריאות AI חיות בתשלום.

סריקה לפני העלאה: 832 blobs היסטוריים וכל קובצי המקור והבנייה נבדקו למפתח השירות האמיתי, מפתחות ספקים, private key, פרטי SSH וכתובת IP של השרת. לא נמצאו סודות. התאמה בודדת בקובץ WASM ישן הייתה רצף בתוך base64 של בינארי OCR; לאחר פענוח ואימות חתימת WASM לא נמצא שם מפתח. זו סריקה לפי דפוסים ובדיקה ממוקדת, לא הוכחה מתמטית שאין כל סוד אפשרי. רק כתובת API ציבורית ושרתי ספקים מאושרים נחוצים בבנייה; בדיקות של כתובות זדוניות הן fixtures סינתטיים ואינן יעדי מוצר.

בדיקת HTTPS אמיתית, מתוך השרת וממחשב Windows, החזירה health 200. בלי מפתח התקבל 401; Origin זר 403; יעד פנימי מזויף 400. שליפה של המהדורה העברית של מרטאג החזירה 200, שם, מחבר, הוצאה, סוג כריכה, שפה, עמודים, ISBN, תאריך, סדרה ומספר וכן כריכה מ־`m.media-amazon.com`. פנייה שנייה שירתה cache, גם אחרי החלפת container, בלי פנייה נוספת למקור. הכריכה הוחזרה ככתובת; תמונת הכריכה לא הורדה במסגרת בדיקת השרת.

חיפוש רגיל באמצעות curl מתוך Oracle קיבל 202 עם גוף ריק; ניסיון urllib קודם נכשל בלולאת redirects. זו ראיה שהחיפוש לפי שם אינו יציב מהשרת הזה, גם כאשר דף ספר כן נשלף. אין עקיפה, התחברות או proxy בתשלום. בדיקה זו אינה מוכיחה שכל הספרים נגישים. בדיקת ISBN אמיתית `9789655851168` דרך `/v1/search` החזירה 200 ומועמד אחד; בחירתו משתמשת בחוזה פרטי המהדורה. חיבור Goodreads עדיין כפוף למגבלות המקור המתועדות במחקר.

השירות צרך כ־31.75MiB ו־0.01% CPU במדידה אחרי השליפה. n8n, Postgres ו־NPM שמרו על אותם זמני startup ו־restart count 0. מגבלות Docker אומתו ב־inspect. בדיקת עומס חריגה לא הורצה על שרת המשתמש.

## תפעול ונסיגה

מצב: `sudo docker inspect library-goodreads --format '{{.State.Health.Status}}'`. שימוש: `sudo docker stats --no-stream library-goodreads`. עצירה: `sudo docker stop library-goodreads` בלבד. הדבר אינו משנה n8n, ספרים במכשיר או מטמון ומכסה בדיסק. אין למחוק את מסד המכסה כדי להתגבר על חסימה.

קובץ `install.sh` מיועד להתקנה ראשונה בלבד ונכשל אם נתיב השירות או קובץ הפרוקסי כבר קיימים. בעדכון יש לבנות תמונה חדשה לפני עצירת השירות, לשמר את אותם mounts ומגבלות, ולהחליף רק את ה־container הזה. resolver בפרוקסי מתעדכן כל 30 שניות; בהחלפה ייתכן 502 זמני עד התעדכנות DNS. יש לבדוק health מקומי וחיצוני לפני הכרזת הצלחה. קובץ הפרוקסי של השירות ניתן להסרה בנפרד, אחרי בדיקת הנתיב המדויק ו־`nginx -t`, בלי לשנות את route הראשי.
