# שלב 14 — מדידה לפני אופטימיזציה

מקור: WORK_PLAN.md שלב 14, מחזור 7 ופרק 8.3. נעילת התשלומים וכללי האוטונומיה ב־DECISIONS.md חלים. אין סוכנים נוספים. אין הכנסת נתוני עומס לספריית המשתמש.

1. ליצור datasets דטרמיניסטיים ומסומנים כסינתטיים: 1,000 ספרים עם תמונות, עותקים והשאלות; 5,000 ספרים, 8,000 עותקים ו־10,000 השאלות היסטוריות. לכלול סדרה ארוכה, מדפים עמוקים, אנשים ועותקים מושאלים; קשרים ו־IDs תקינים.
2. להריץ בגרסת production באוריג׳ין/פרופיל נפרדים. מדידת פתיחה קרה וחמה, לפחות 30 חיפושים, שינוי/השאלה עד commit וציור, גלילה, נפח Blob ואחסון בפועל. לתעד Chrome/מחשב/viewport/תנאי רשת ו־p95; מדידת desktop אינה מדידת iPhone.
3. להשוות ליעדי התוכנית: חיפוש 300ms p95 ב־1,000, פתיחה מקומית 2s, שינוי/השאלה 500ms p95, bundle ליבה 300KB gzip. לספור chunks ראשוניים בנפרד מעצלות; לבדוק thumbnails 240–320px וממוצע יעד 50KB.
4. רק אחרי פער מדוד לשנות רינדור/אינדקסים/עיבוד. מועמדים לבדיקה: עלות כל שורות BookList, מנויי Thumbnail, חיפוש ואינדקס אותיות בגלילה. לשמר רשימה רציפה, סדרות, אותיות, focus ונקודת גלילה. לא להוסיף worker/ספרייה רק לפי השערה.
5. לבדוק quota exceeded ושימור נתונים לאחר כישלון, ביטול עיבוד ותמונות רבות. לחזור על בדיקות החיפוש/השאלות/צילום/PWA אחרי שינוי, ביקורת בחמישה צירים וניסוי רגישות הפיך לפני מיזוג.
6. להכין מסלול נפרד ומוגן להרצת dataset פיקטיבי במכשיר היעד ולשאול את המשתמש כשיש קישור נגיש. התקנה, מצב טיסה, VoiceOver, Safari לעומת PWA ו־traces אמיתיים נשארים NOT RUN עד ראיה. מחזור 7 אינו PASS מלא בלי אלה; ממשיכים בעבודה העצמאית המורשית.

לאחר שלב 14 נותרו שלבים 15–20 וכן ביקורת דרישות מלאה: מיזוג זהויות מחברים/תגיות/אנשים, מחיקה מפורשת עם היסטוריית השאלות וגיבוי, תמונות נוספות לספר, ספקים חיים ובדיקות משתמש חסרות. אין לסמן את הפרויקט הושלם על סמך כותרות שלבים בלבד. אין להחליף את GitHub Pages לפני הפריסה המתוכננת והבדיקות המתאימות.
