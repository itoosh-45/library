# שלב 17 — שדרוג והתאוששות

מטרה לפי WORK_PLAN v1.2: T23 מכל schema ששוחרר (1 ו־2), שדרוג אטומי וכשל, חסימת לשונית, גיבויים ישנים, מעבר origin/נתיב ותאימות קוד; T20 עדכון worker לצד המסד. מקור אישי אינו נמחק. אישור המשתמש לעבודה לפי הספר ולמיזוג כל שלב חל; אין שער אישור חוזר.

שינוי מוגבל בזרימה קיימת: שדרוג 1→2 משלים collapsed רק כשהשדה חסר; אין schema חדש ללא צורך. אתחול בודק גרסה native במפורש כי Dexie עשוי לפתוח schema גבוה מהמוצהר. אירוע versionchange עוצר שמירות מאוחרות ושומר את הטופס על המסך, עם שחרור חיבור מפורש; blocked מאפשר המתנה או ביטול בלי איפוס. קוד חדש אינו מקטין גרסת מסד.

הבדיקות על מסדים סינתטיים: כל הטבלאות/בתים של תמונות/השאלות/טיוטות בשדרוג ובפתיחה חוזרת; כשל transaction אחרי מחיקות בעסקה מתגלגל אחורה; JSON 1–8 וייצוא חוזר; native blocked/versionchange בין שני חלונות; מעבר כתובות עם גיבוי ושמירת מקור. מדריך עדכון/תיקון קדימה/שחזור ומפת app↔schema↔backup יתעדו מה באמת נתמך. תאימות לקוד היסטורי אינה נובעת מהצלחה של קוד נוכחי.

צמצום ניסויים: אין בחירת ספרייה נוספת או מדידת ביצועים חוזרת. בדיקות בטיחות נדרשות נשמרות; בדיקות עוברות חוזרות רק בעקבות שינוי. בדיקת משתמש תישלח כשהמעבר ניתן לסקירה ותישאר פתוחה בלי לעצור עבודה בלתי תלויה. אין תשלום, קרדיטים, billing או שינוי n8n/Pages.
