# שלב 13 — PWA, אופליין ועדכון בטוח

מקור: WORK_PLAN.md שלב 13 ומחזור 7. אישור עבודה אוטונומית ונעילת התשלומים ב־DECISIONS.md. שלבים 11–12 נבנו ונבדקו מקומית; ראיות הטלפון וה־benchmark נשארות פתוחות.

1. manifest תחת base /library/, שם/שפה/כיוון RTL, start_url/scope, display standalone ואייקוני PNG רגילים ו־maskable בכמה גדלים. עיצוב האייקון מתאים לספרייה המקומית.
2. service worker של build בלבד, עם רשימת assets מדויקת הכוללת shell, כל chunks העצלות, fonts ואייקונים. אין cache של API, Gemini, תמונות/keys/exports/בקשות POST. fallback ניווט תחת scope בלבד, בלי השתלטות על ניסוי המצלמה הקיים.
3. רשת ומצב התקנה בטקסט ברור. זיהוי וחיפוש ספקים אינם מוצגים כזמינים אופליין; הוספה/עריכה/ספר/השאלה/חיפוש מקומי ממשיכים. הוראות iPhone ומגבלות מקור־אחסון מפורשות, ללא הבטחה ש־Safari ו־PWA חולקים DB.
4. בקשת storage persistence מפורשת ותוצאה נתמכת/נדחתה/לא זמינה; עדיין להציע גיבוי. בלי שירות חדש או שינוי חיוב.
5. עדכון שממתין לפעולת משתמש, בלי skipWaiting אוטומטי או רענון בזמן עריכה, כתיבה, vision או ייבוא. בדיקת busy/draft לפני reload, שמירה על DB, ניקוי caches גרסה קודמת רק אחרי הפעלה בטוחה.
6. בדיקות production באוריג׳ין מקומי מבודד: install/control, offline reload, ספר והשאלה ללא רשת, chunks עצלים/גופנים/base, API אינו cached, עדכון v1→v2 בזמן עריכה ונשארות הרשומות. אין שימוש בספריית המשתמש או שינוי Pages בשלב הקוד.

התקנה ב־iPhone ומצב טיסה מאוריג׳ין staging אמיתי מחייבים ראיות משתמש/פריסה; עד אז NOT RUN. מדידות storage ו־p95 מורחבות בשלב 14. אין חיוב, קרדיטים, מנוי או fallback בתשלום.
