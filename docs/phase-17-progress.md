## מה נבנה

השדרוג 1→2 משלים collapsed רק כשהוא חסר; bool קיים נשמר והטרנספורמציה idempotent. אין schema חדש ללא צורך. אתחול בודק גרסת IndexedDB native לפני כתיבה: בבדיקה התברר ש־Dexie.open עשוי לקבל מסד חדש יותר באמצעות fallback, ולכן אין הסתמכות על VersionError בלבד.

LibraryStartup מציג blocked עם המתנה/ביטול בלי איפוס; versionchange משאיר את הטופס ומשבית שמירות מאוחרות בשכבת transaction. dialog נגיש מופיע גם מעל עורך modal. המשתמש משחרר חיבור במפורש; אין רענון אוטומטי או טענה שטקסט שלא נשמר נכתב למסד. ביטול פתיחה גובר על תוצאת async מאוחרת. הוספו RecoveryPanel בהגדרות ו־update-recovery-runbook.md.

## ביקורת

נכונות: version transaction אטומי, טרנספורמציה idempotent ושדות קיימים נשמרים; חסימת גרסה native לפני כתיבה, ביטול וכתיבה מאוחרת, קשרים ותמונות וגיבויים ישנים נבדקו. קריאות: lifecycle ו־Startup נפרדים משירותי הנתונים; מסך ההסבר נפרד, בלי כלי migration כללי. ארכיטקטורה: שם DB/schema נשמרים; worker נגזר מ־scope ו־base; reuse של שירותי הגיבוי. אבטחה: אין איפוס/הקטנת גרסה במוצר, אין סודות ב־URL/log/cache, שתי מעטפות לא מוחקות זו את זו; native mutations קיימות רק בבדיקות מבודדות. ביצועים: אין dependency נוספת, core בתוך התקציב, אין מדידות השוואה נוספות.

ניסוי ביקורת הפיך יחיד בעותק פרטי: הוסרה חסימת transaction בעת upgradePending; בדיקת lifecycle נכשלה כי שמירת השם הצליחה. החזרת התנאי העבירה את אותה בדיקה. הקוד הפעיל לא שונה לצורך הניסוי, ופלטים/עותקים פרטיים מוחרגים מ־Git.

התאמת נתיב הוסיפה תיקון שנדרש מהתרגיל: /library/ היה קבוע ב־manifest/רישום worker/precache. עתה HTML/register משתמשים ב־BASE_URL, manifest בנתיבים יחסיים ו־worker ב־scope בפועל. namespace המעטפת הרגילה נשמר כדי לעדכן cache ששוחרר; נתיבים אחרים משתמשים ב־prefix נפרד שאינו נכלל בניקוי הישן. בנייה מתירה base של נתיב מוחלט, לא URL זר/נתיב יחסי שאינו נתמך באופליין.
