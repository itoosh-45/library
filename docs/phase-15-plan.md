# שלב 15 — JSON מלא ומיזוג בטוח

המשתמש חידש עבודה ב־3 באוקטובר 2026; העצירה אחרי שלב 14 אינה בתוקף עוד. נעילת התשלומים וכל יתר הגבולות נשמרים. WORK_PLAN.md לא משתנה. מקור: סעיפים 7.2/7.3, שלב 15, T19.

התכנון מרחיב את מסלול הגיבוי הקיים: יצוא במעטפת my-library-backup/formatVersion 8, schema 2, tables, images, manifestCounts ו־checksums. אימות v1–v7 נשמר; המעטפת החדשה עוברת אותו אימות מלא של שדות, קשרים, היסטוריה ותמונות. הגבלת הקובץ הועלתה ל־150MiB בעקבות יעד הניסוי בסעיף 8.3; אין שינוי DB או dependency. קובץ אינו מוצפן, checksum אינו הוכחת מקור, ומפתחות/cache/תשובות ספק גולמיות מוחרגים.

״הופק גיבוי״ ו״אושר שנשמר ונבדק״ מוצגים בנפרד עם תזכורת בתוך המסך אחרי 30 יום. זמני הגיבוי עצמם אינם מבטלים fingerprint של גיבוי מגן; שינוי כל נתון אחר כן. הורדה אינה הוכחת שמירה ב־Files.

מיזוג: preview ללא כתיבה, כל הנתונים הקיימים נשמרים אלא אם המשתמש בוחר נתון בקובץ בסתירה. באותה libraryId המזהים נשמרים; שינויים מוצגים עם revision ובחירה לכל סתירה. בחירת ספר מהקובץ מקדמת revision כדי שלא להכשיר כרטיס ישן. בין ספריות ממפים UUID לכל טבלה באופן דטרמיניסטי לפי מקור/יעד/טבלה/מזהה, כולל קשרים וטיוטות. אין איחוד מחברים/אנשים לפי שם. שמות אוספים שמתנגשים מוצעים כאוספים נפרדים בשם מובהק; ספרים בעלי מזהה/שם דומה נשארים נפרדים אחרי אישור מפורש. ייבוא חוזר משתמש במיפוי הקודם ולא מוסיף שוב את אותן רשומות. אין מחיקות או שינוי של שם/הגדרות ספריית היעד במיזוג.

כל בחירות הסתירה משולבות בטיוטת Core ומאומתות יחד, לפני כתיבה. ההחלה היא transaction אחת, עם בדיקת fingerprint נוספת בתוכה; רק רשומות שהשתנו נכתבות. מקור פגום, יחסים לא תקינים, השאלות חופפות, שינוי בחלון אחר או abort אינם משנים את DB הפעיל. אין deleteDatabase או רשת במסלול זה.

אימות נדרש: מעטפת v8/ישנות/עתידיות/פגומות, round trip מלא כולל hashes, ID collisions בין ספריות, import חוזר, סתירות revision, עץ/אוספים/היסטוריה/טיוטות, quota ו־abort אמיתי ב־IndexedDB, UI ב־360px, כל הרגרסיות ו־production PWA. ניסוי ביקורת הפיך ומיזוג ל־main לאחר בדיקות. הורדה/שיתוף ושחזור ב־iPhone דורשים סביבת בדיקה נפרדת וממשיכים להיות NOT RUN ללא ראיה.
