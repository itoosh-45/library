# תיקון קלט מפתח Gemini — 3 באוקטובר 2026

המשתמש דיווח שהמפתח נדחה מיד ב״הגדרת המפתח לזיכרון בלבד״. באותו שלב אין כלל בקשת Google: regex מקומי התיר רק אותיות/ספרות/קו/מקף עד 200 תווים ושדה password נחתך ב־200. זו הנחה בלתי מתועדת על פורמט מפתח, ולא בדיקת תקינות ספק. לא התקבל מפתח משתמש ולא ידוע מה בדיוק במפתח שלו הפעיל את המסנן. [Google מתעדת מפתחות standard ו־auth](https://ai.google.dev/gemini-api/docs/api-key); אין להסתמך על צורת מפתח ישנה לאימות הרשאה.

App 0.17.1 מקבל token של 20–4096 תווי ASCII נראים, כולל סימני פיסוק, ומסיר סימני כיווניות/רוחב אפס של העתקה ורווחי קצה. רווחים פנימיים, CR/LF פנימיים, Unicode אחר ומפתח גדול מדי נדחים בלי לחשוף תוכן. שדה הקלט באותו גבול ואינו חותך מפתח ב־200. הממשק מבהיר ששמירה בזיכרון אינה בדיקת חיבור. אין שינוי במודלים, endpoint, schema2/JSON8, מפתחות בזיכרון בלבד, הסכמה/Free, עצירה ב־429 או fallback. לא בוצעה קריאת ספק אמיתית ואין חיוב.

בדיקות: 14 בדיקות phase10 עברו; רגרסיה ממוקדת בודקת token סינתטי ארוך עם נקודות וסימני העתקה, אפס בקשות בהגדרה, header מדויק בבקשה מדומה, קלט זדוני/ארוך/שבור וסוד שאינו serializable. בדיקת דפדפן אחת מאמתת שאין חיתוך, הגדרה ומחיקה ברענון, ללא בקשות Gemini. ניסוי תקלה יחיד החזיר את מגבלת 200 והכשיל את הרגרסיה; אחרי שחזור עברה. lint/typecheck/build נבדקים לפני פרסום; אין צורך בחזרה על ניסויי benchmark/טלפון או חבילות frontend אחרות ללא שינוי רלוונטי.

ביקורת: נכונות — אותה בדיקת header ב־session ובגבול UI; קריאות — נרמול קצר והודעה שאינה קובעת שהספק דחה מפתח; מבנה — תיקון במנגנון הקיים ללא תלות חדשה; אבטחה — ללא רווחי header/תוכן שגיאה/שמירה/רשת בהגדרה, שומר Free ו־consent; ביצועים — חסם 4096. קבלת token מקומית אינה מוכיחה אימות חי, והוא נשאר לבדיקת המשתמש בלי חשיפת מפתח.
